# Single-host CPU VM experiment

This is a **non-production, manual experiment**, not a Nest host agent or a tenant isolation claim. It starts one existing x86-64 Linux installation and a separate raw data disk under QEMU (KVM when `/dev/kvm` is usable, otherwise TCG software emulation). It does not create, format, delete, snapshot or migrate either disk. The guest and its disks must be dedicated to this experiment. Use a disposable host isolated from production and other users; QEMU user networking allows guest access to host services and provides no tenant network policy. No ports are published by this script. There is no ingress, placement, metering, suspend, GPU or automated provisioning.

Requirements: `qemu-system-x86_64`, `flock`, two writable raw disk images, and a guest configured for a serial console, virtio disks and networking. Prepare the OS image using a trusted installation process; this script does not download or verify images. Back up both disks before use. The data disk must be formatted and mounted by the guest using a stable filesystem label or UUID, with an `/etc/fstab` entry. `nofail` with a device timeout lets boot continue when the volume is missing; the box then does not start, because its user unit and config live on the volume. Do not format a disk without independently identifying it. Mount the volume before starting the box, and configure the box's data directory **and its pairing config and any CLI login state** on that volume; verify their actual paths with the installed box version. The ordinary single-owner `kestrel-box` pairing and `/box/self` flow applies; use a test control plane and test credentials only. The guest must have the box's normal systemd and sandbox prerequisites, and use `guaranteed` provisioning. See [BYOB setup](../../docs/byo-box.md#install-your-own-box). The CLI's default config and data paths are separate, so moving only its data directory is insufficient. Do not put credentials in the script, QEMU arguments, logs or source control.

Run `./scripts/nest-prototype/run.sh /path/to/os.raw /path/to/data.raw` on the test host. QEMU attaches the OS disk first and the volume second; identify the volume by label or UUID rather than assuming device names. It holds exclusive advisory locks on both files until QEMU exits; other tools must honor those locks. Shut down cleanly **from the guest** and wait for QEMU to exit before moving or backing up either image. An unexpected host failure can still corrupt guest data. Console access and both images expose the owner's data and credentials; restrict host access and protect and encrypt backups.

To validate on an eligible host, pair a test box and create a thread and a workspace file, then shut down the guest cleanly. Restart with the same two images, confirm the volume is mounted before the box service, and verify the same thread, workspace file and pairing survive and the box can authenticate via the test control plane. Also test that boot without the volume does not start the box. Record guest/image versions and results with the change that reports them. Software emulation is intentionally slow and does not establish capacity, performance, hardware isolation or billing accuracy.

Test guests on Ubuntu 24.04 need `kernel.apparmor_restrict_unprivileged_userns=0` (for example in `/etc/sysctl.d/`): the box's bwrap sandbox needs unprivileged user namespaces, and otherwise agent tasks fail with `bwrap: setting up uid map: Permission denied`. Desktop tools need `weston` in the guest.

The `packages/host` CLI (`kestrel-host`) adds local lifecycle commands, a per-incarnation VM identity, data-volume label and UUID checks, and crash reconciliation. A real host layer still needs authenticated lifecycle commands, encrypted storage, ingress and network isolation, resource enforcement, and host-side usage collection. Any usage records must coordinate with the metering contract and cannot be treated as billable until collection and reconciliation are verified. GPU passthrough and suspend require a separate hardware experiment; this CPU-only script does neither.
